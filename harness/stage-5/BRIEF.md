# BRIEF: Этап 5 — внешний вид
Дата: 2026-09-21

## Формулировка своими словами
Логика и тесты не трогаем — меняем только разметку и подключаем Pico CSS (classless, один `<link>`), чтобы страницы перестали быть голым HTML. Разметка переводится на семантические теги (`header`, `main`, `footer`, `table`, `form`, `fieldset`), чтобы Pico сам применил стили без единого класса. Два жёстких правила: состояние — словом, не только цветом (уже так с Этапа 2, просто не ломаем при вёрстке); на телефоне ничего не обрезается и не требует зума, таблицы либо влезают, либо скроллятся сами по горизонтали.

## Набросок (5 минут, по заданию — что сверху, что снизу)
```
+--------------------------------------------------+
| header: заголовок сайта + текущее состояние       |
|         (слово + акцентный цвет)                  |
+--------------------------------------------------+
| main:                                             |
|   [ график Chart.js + переключатель видов данных ]|
|   (во всю ширину)                                 |
|                                                    |
|   [ таблица среднее±σ ]  [ таблица последних 50 ] |
|   (рядом на десктопе, друг под другом на телефоне,|
|    вторая — в обёртке с горизонтальным скроллом)  |
+--------------------------------------------------+
| footer: ссылки /admin (или /login, если не вошёл) |
+--------------------------------------------------+
```
`/login` и `/admin` — тот же header/footer, в `main` — одна форма в один столбец (Pico растягивает поля формы на всю ширину сам).

## Дизайн-план (коротко, скилл `frontend-design`)
- **Предмет и аудитория**: приборная панель промышленного мониторинга (температура/давление/вибрация), а не обобщённый SaaS-дашборд — визуальный язык из мира приборных щитов/телеметрии, не из мира лендингов.
- **Цвет** (4 именованных значения, поверх Pico через CSS-переменные, тёмная тема `data-theme="dark"`):
  - фон панели `#12181f`, поверхность (таблицы/карточки) `#1b232c`, текст `#dfe6ec`, акцент Pico (`--pico-primary`) `#2fb0c7` — приборный сине-голубой, не дефолтный SaaS-синий и не терракотовый.
  - Цвета состояний — приглушённые, не «неоновые»: норма `#3fae59`, предупреждение `#d99b2b`, неисправность `#d1483f`. Акцентный цвет используется только для состояния — не конкурирует с другим «брендовым» цветом.
- **Типографика**: заголовки/подписи — системный шрифт Pico по умолчанию (без загрузки лишних шрифтов — один `<link>`, как в задании); числовые значения в таблицах — моноширинный системный шрифт (`ui-monospace`) — приборные показания читаются как показания, а не как текст. Без ALL-CAPS лейблов, без «эйброу»-подписей над блоками, без стрелок в кнопках.
- **Компоновка**: без центрирования по «маркетинговому» шаблону — контент выровнен по левому краю, читается сверху вниз как список показаний, а не как промо-страница. Одна колонка на телефоне, две — на десктопе (пороговое поведение через CSS `grid`, не через JS).
- **Принципы**: (1) состояние — слово, потом цвет; (2) один акцент — только для состояния, никакой декоративной подсветки; (3) числа — моно, текст — обычный; (4) без карточек-с-тенями, без градиентов, без нумерации, если контент не последовательность.

## Критерии успеха
- [ ] Pico CSS подключён одним `<link>` (classless, CDN), Bootstrap/Tailwind не используются
- [ ] `/`, `/login`, `/admin` переведены на семантическую разметку
- [ ] Состояние показано словом и цветом (не только цветом)
- [ ] На 390px ничего не обрезано и не наезжает, таблица «последние показания» скроллится по горизонтали внутри своей обёртки, а не ломает страницу
- [ ] Скриншоты на 390 / 768 / 1440 через `layout-qa` (настоящий Chromium) — приложены к REPORT
- [ ] `pytest` зелёный без единого изменения в тестах — логика не менялась
