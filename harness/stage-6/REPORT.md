## Отклонения от плана
Одно техническое, найденное и исправленное в процессе: изначальный вариант ветвления SQL (`if BACKEND == "mysql": PLACEHOLDER = ...` на уровне модуля) вычислялся один раз при импорте — та же ошибка, что чинили с `DB_PATH` на Этапе 3: `monkeypatch.setattr(db, "BACKEND", "mysql")` в тестах не имел бы эффекта, потому что `PLACEHOLDER`/`CREATE_READINGS` и т.д. уже были бы зафиксированы под тот бэкенд, что стоял в `.env` при запуске тестов. Переделано на функцию `_sql(key)`, читающую `BACKEND` заново при каждом вызове — так же, как раньше `path=None` вместо `path=DB_PATH`.

## Часть B — хостинг на Beget (промежуточный статус)

Выполнялось вместе с пользователем: регистрация и все технические шаги на сервере — пользователь сам, через свой терминал (пароли и SSH-сессия я не трогаю); я — навигация по панели в общем браузере (с явного согласия), диагностика ошибок, генерация не-аккаунтных секретов.

### Что сделано и реально проверено
- Аккаунт на Beget зарегистрирован, тариф Start (пробный период 30 дней, оплаты не было).
- Сайт `mcfluury.beget.tech` — использован существующий технический поддомен (создался автоматически при регистрации), отдельный заводить не стали.
- Репозиторий на GitHub переключён с приватного на публичный — понадобилось для `git clone` с сервера (см. `DECISIONS.md`); история проверена на секреты перед переключением.
- Код выложен на сервер: SSH → Docker-окружение → `git clone` → venv внутри `public_html/venv` → зависимости (Passenger не видит `pip install --user` пакеты, см. `LESSONS.md`).
- MySQL создана в панели, серверный `.env` заполнен (новые секреты, отдельные от локальных), `db.init_db()` реально создал таблицы и засеял пороги в боевой MySQL — проверено выводом `backend: mysql`, `thresholds: {...}`.
- `passenger_wsgi.py` подключён через `.htaccess` (`PassengerEnabled`/`PassengerAppRoot`/`PassengerPython` на venv) — панель не даёт отдельного переключателя «тип сайта», понадобилась ручная настройка. `PassengerFriendlyErrorPages on` помог увидеть реальный traceback вместо непрозрачной страницы ошибки.
- Cron настроен через «Планировщик заданий» — `*/5 * * * *`, команда `cd .../public_html && venv/bin/python simulator.py`. Проверено вживую: показание появилось в `/api/readings` в `01:40:01` без моего/пользовательского участия, страница `/` показала реальные данные и живое состояние («предупреждение»).

### Что осталось
- **HTTPS через Let's Encrypt** — не нашёл рабочий пункт в актуальной панели Beget за разумное время (перепробовал разделы «Домены», «Сайты», их иконки — везде либо не то, либо разрушительное действие типа «Открепить домен», которое НЕ выполнял). Статья базы знаний Beget описывает путь через «Домены и поддомены → кнопка у домена → Управление SSL сертификатами», но в наблюдаемой версии панели этого пункта нет — либо переехал, либо недоступен для технического поддомена `*.beget.tech` (в отличие от полноценно добавленного домена). Решение: пользователь открывает тикет в поддержку Beget. Пока сайт работает по `http://`, `API_URL` в серверном `.env` временно указывает на `http://`.
- Из-за отсутствия HTTPS **пункт «ссылка открывается с телефона по https» ещё не закрыт**, как и требование «сайт живёт минимум неделю» (отсчёт по факту начался сейчас, 2026-09-22, с рабочего HTTP-сайта и cron).
- Будет отдельное обновление этого REPORT, когда решится вопрос с HTTPS.
