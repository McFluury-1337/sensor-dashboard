# RUNBOOK: Этап 6, Часть B — хостинг на Beget

Эти шаги выполняете вы сами. Регистрация аккаунта, выбор тарифа и платёж —
не то, что Claude делает за вас ни при каких обстоятельствах (нет доступа,
и это осознанное ограничение). Часть A (код: MySQL-бэкенд, `passenger_wsgi.py`,
переменные окружения) сделана и запушена — см. `harness/stage-6/REPORT.md`.

## 1. Регистрация и тариф
Зарегистрироваться на beget.com, выбрать самый дешёвый тариф виртуального
хостинга.

## 2. Создать сайт и поддомен
В панели: раздел «Сайты» → создать сайт, привязать домен/поддомен. Beget
рекомендует называть сайт так же, как домен — меньше путаницы в путях.

## 3. SSH-доступ и окружение
```bash
ssh ваш_логин@ваш_логин.beget.tech
ssh localhost -p222
```
Вторая команда переводит в Docker-окружение, где живёт Python (подтверждено
базой знаний Beget: https://beget.com/ru/kb/how-to/web-apps/python).

## 4. Выложить код
Самый простой вариант — клонировать репозиторий прямо на сервере:
```bash
git clone https://github.com/McFluury-1337/sensor-dashboard.git
cd sensor-dashboard
pip3 install -r requirements.txt --user --ignore-installed
```
Флаг `--user` обязателен в их окружении (Docker + POSIX ACL между сайтами).

## 5. MySQL
В панели — раздел баз данных, создать MySQL-базу и пользователя. Записать
хост, порт, имя базы, пользователя, пароль.

## 6. `.env` на сервере
Через файловый менеджер или SSH создать `.env` рядом с `app.py` (по образцу
`.env.example`), с `DB_BACKEND=mysql` и реальными данными из шага 5, плюс
свои `API_KEY`/`ADMIN_PASSWORD`/`SECRET_KEY` — **новые**, не те, что в
локальном `.env` на вашем компьютере.

## 7. Passenger подхватывает сайт
Здесь честно: точный пункт меню «тип сайта → Python/Passenger» в текущей
панели Beget не подтверждён документацией — поиск по их базе знаний и
Google не дали прямого попадания на этот конкретный экран. `passenger_wsgi.py`
уже в репозитории и рабочий (`from app import app as application` — стандарт
Phusion Passenger, не зависит от хостера), но конкретный переключатель,
где Beget должен узнать «это Python-сайт», нужно поискать в настройках
сайта в панели или уточнить в их поддержке (тикет из панели — их же
рекомендованный способ по многим статьям базы знаний).

## 8. HTTPS
В панели сайта — раздел SSL, включить Let's Encrypt.

## 9. Cron для симулятора
Раздел «Cron» в панели, задача вида:
```
*/5 * * * * cd /путь/к/сайту && /путь/к/venv/bin/python simulator.py
```
Раз в 5 минут — соответствует «раз в несколько минут» из задания. Важно:
`API_URL` в серверном `.env` должен указывать на настоящий домен сайта, а
не на `127.0.0.1`.

## 10. Проверка
Открыть ссылку с телефона по `https://`, убедиться, что сертификат зелёный,
подождать пару циклов cron — состояние и график должны обновляться сами,
без ручного вмешательства. Критерий этапа требует, чтобы сайт прожил так
минимум неделю до сдачи — это не проверяется за один присест.

## Если что-то пошло не так
Присылайте логи/скриншоты конкретного шага — разберём вместе. Не
пытайтесь угадывать за поддержку Beget: если панель не даёт очевидного
пункта из шага 7, тикет в их поддержку быстрее, чем гадание по старым
статьям.
