# BRIEF: Этап 9 (бонус) — выгрузка показаний в CSV за период
Дата: 2026-09-23

## Формулировка своими словами
Из раздела задания «Если оказалось легко»: выгрузка показаний в CSV за период. Пользователь задаёт две даты (с/по) — сайт отдаёт CSV-файл со всеми показаниями в этом диапазоне (время, температура, давление, вибрация). Роут читает из уже существующей таблицы `readings`, ничего нового в БД не создаётся.

## Набросок
```
GET /api/readings/export.csv?start=YYYY-MM-DD&end=YYYY-MM-DD
    → оба параметра обязательны, формат даты проверяется → иначе 400
    → db.get_readings_in_range(start, end + "T23:59:59.999999")
    → text/csv, Content-Disposition: attachment
```
На главной странице — маленькая форма (два `<input type="date">` + кнопка) рядом с таблицей «Последние показания», обычный GET-form без JS — браузер сам скачивает файл.

## Критерии успеха
- [ ] `GET /api/readings/export.csv` без `start`/`end` → 400
- [ ] Некорректный формат даты → 400
- [ ] Показания вне диапазона не попадают в выгрузку, внутри — попадают
- [ ] `Content-Type: text/csv`, `Content-Disposition: attachment; filename=...`
- [ ] Роут публичный, без ключа — как и `GET /api/readings` (тот же прецедент, задокументирован ранее)
- [ ] Форма на главной странице реально скачивает файл, без JS
- [ ] `pytest` зелёный, новые тесты — красные до реализации
