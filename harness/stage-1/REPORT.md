# REPORT: Этап 1 — локальный сайт с базой
Дата: 2026-09-21

## Что сделано
- `db.py` — единственный модуль работы с БД: `init_db()` создаёт таблицу `readings` (id, timestamp, temperature, pressure, vibration) в SQLite-файле `sensors.db`, `insert_reading()` пишет одну запись, `get_latest_readings(limit)` читает последние записи по `id DESC`. Вся остальная логика ходит в БД только через эти функции — задел под переезд на MySQL без переписывания вызывающего кода.
- `simulator.py` — генерирует одну запись показаний за запуск: случайно выбирает состояние (норма/предупреждение/неисправность) и берёт `random.normalvariate(mu, sd)` по трём параметрам с mu/sd из НИР, пишет через `db.insert_reading`.
- `app.py` — Flask-приложение, один роут `/`, показывает голую HTML-таблицу последних 50 записей (время, температура, давление, вибрация) через `db.get_latest_readings(50)`.
- `requirements.txt` — единственная внешняя зависимость `flask`.
- `.gitignore` — исключает `__pycache__/`, `.venv/`, `sensors.db` (тестовая БД и venv не должны попадать в репозиторий).

## Проверка критерия
Критерий этапа: «`python app.py`, открыл `localhost:5000`, увидел таблицу с данными. Запустил симулятор ещё раз, строк стало больше.»

Проверено вживую, а не только чтением кода:
1. `pip install -r requirements.txt` в отдельном `.venv` — Flask 3.1.3 установлен без ошибок.
2. Замерил число строк в `readings` через `db.get_latest_readings` — было 11.
3. Запустил `python simulator.py` (запуск №1) — стало 12 строк.
4. Запустил `python simulator.py` ещё раз (запуск №2) — стало 13 строк. Прирост ровно +1 за запуск, как и должно быть для «одна запись за запуск».
5. Запустил `python app.py` как реальный HTTP-сервер и получил страницу через `curl http://127.0.0.1:5000/` — HTML-таблица со всеми текущими записями, значения отформатированы `.2f`, порядок совпадает с БД (новые сверху). Сервер остановлен после проверки.
