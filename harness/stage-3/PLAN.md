## Альтернативы

- `python-dotenv` вместо своего загрузчика `.env`: отвергнуто — новая зависимость требует обоснования по правилам проекта, а десяток строк на стандартной библиотеке делают то же самое для одного файла `.env`.
- `requests` вместо `urllib.request` в `simulator.py`: отвергнуто по той же причине — для одного JSON POST стандартной библиотеки достаточно, `requests` был бы зависимостью «на вырост».
- Передавать состояние (`state`) от симулятора в API и писать его в `readings`: отвергнуто — то же решение уже принято на Этапе 2 (пороги можно поменять в админке на Этапе 4, зашитое на момент вставки состояние потом будет врать).
- Защищать `GET /api/readings` тем же ключом, что и `POST`: рассмотрено, но не обязательно — эндпоинт только читает то же самое, что уже видно на `/` без всякой авторизации; добавлять защиту чтения без причины — лишняя сложность для пет-проекта.
