# REPORT: Этап 8 (бонус) — уведомление в Telegram при переходе в «неисправность»
Дата: 2026-09-23

## Что сделано
- Новый модуль `notifications.py`: `is_new_fault(previous_state, current_state)` (чистая функция) и `send_telegram_alert(message)` (один HTTP POST через `urllib.request`, без сторонних библиотек).
- `tests/test_notifications.py` — 9 тестов, написаны и красными прогнаны (`ModuleNotFoundError: No module named 'notifications'`) до появления файла реализации — только после этого написан код.
- `app.py`: общий хелпер `_record_reading()` — убрал дублирование логики вставки показания между `/api/readings` и `/admin/readings`; после вставки сравнивает состояние до/после и вызывает `send_telegram_alert()` при переходе в «неисправность». Текст сообщения переиспользует уже существующую `build_state_reason()`.
- `.env.example` дополнен `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` с комментарием, как их завести.

## Отклонения от плана
Одно техническое, найденное и решённое в процессе: живая проверка изначально не срабатывала — `send_telegram_alert()` не бросала исключений (перехватывает `OSError`), но и сообщение не приходило. Прямой вызов без перехвата вскрыл `SSLCertVerificationError` — Python с python.org на этом Mac не имел заполненного `cert.pem`. Почитано в `LESSONS.md`, исправлено официальным скриптом `Install Certificates.command` (запущен с явного подтверждения пользователя, так как трогает файлы в `/Library/Frameworks`). После фикса потребовался ещё и перезапуск уже запущенного dev-сервера — второй нюанс, тоже в `LESSONS.md`.

## Сюрпризы
- `except OSError` в `send_telegram_alert()` — осознанное решение (не ронять сохранение показания при сбое Telegram), но оно же скрыло реальную причину сбоя при отладке. Не убирал перехват из продакшен-кода (это правильное поведение для рантайма), но при диагностике пришлось временно вызывать `urlopen` напрямую в консоли, без обёртки, чтобы увидеть настоящую ошибку.
