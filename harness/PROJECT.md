# Карта проекта: sensor-dashboard

## Что это
Пет-проект: веб-дашборд на Flask, показывающий показания датчиков (температура, давление, вибрация), которые генерирует локальный симулятор на основе генератора из НИР автора. Делается для практики полного цикла веб-разработки — от БД до хостинга.

## Стек
- Python 3.14 (venv в `.venv/`, в репозитории не хранится)
- Flask 3.1.3 — веб-сервер, одна страница без шаблонов и стилей
- SQLite (файл `sensors.db`, в репозитории не хранится) — хранилище показаний, доступ только через `db.py`, чтобы позже можно было переключиться на MySQL

## Структура
```
app.py            # Flask-приложение, страница "/" с таблицей последних 50 записей
db.py             # единственный модуль работы с БД (init/insert/select) — точка переезда на MySQL
simulator.py      # генерирует одну запись показаний (норма/предупреждение/неисправность) и пишет через db.py
requirements.txt  # внешние зависимости (flask; sqlite3 — встроенный)
harness/          # PROJECT.md и другие харнесс-артефакты
```

## Ключевые модули и точки входа
| Модуль | Где | За что отвечает |
|--------|-----|-----------------|
| `db.py` | `db.py` | Подключение к SQLite, создание таблицы `readings`, вставка и чтение записей. Единственное место с SQL. |
| `simulator.py` | `simulator.py` | Выбирает состояние (normal/warning/fault), генерирует temp/pressure/vibration через `random.normalvariate` по mu/sd из НИР, пишет одну запись за запуск. |
| `app.py` | `app.py` | Flask-роут `/` — читает последние 50 записей через `db.py`, рендерит голую HTML-таблицу. |

## Как запустить / проверить
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python simulator.py      # добавить одну запись в sensors.db (можно запускать многократно)
python app.py             # запустить сайт на http://127.0.0.1:5000/
```
Тестового набора (pytest и т.п.) в проекте нет — проверка ручная: запустить симулятор несколько раз, открыть страницу, свериться с БД (`db.get_latest_readings(50)`).

## Known issues
- `app.py` собирает HTML прямой f-строкой без экранирования — безопасно только пока в таблице нет строковых данных, приходящих извне (сейчас всё из своего симулятора).
- `app.run(debug=True)` — только для разработки, для деплоя нужно будет заменить на прод-WSGI сервер.
- `simulator.py` пишет ровно одну запись за запуск, непрерывного сбора (цикл/планировщик) пока нет — отдельный этап.
- Графиков и логики определения состояния на дашборде ещё нет (см. README) — Этап 1 закрывает только хранение + голый вывод таблицы.
