## 2026-09-21 — Окно графика: последние 50 показаний
- Решение: график Chart.js и таблица на главной странице показывают последние 50 записей из `readings`.
- Почему: то же число уже используется в таблице Этапа 1 (`db.get_latest_readings(50)`) — единообразно, не плодит вторую константу без причины.
- Затронуто: `app.py`, `db.py` (переиспользуем существующую функцию).

## 2026-09-21 — Итоговое состояние показания: «худшее из трёх»
- Решение: если по одному показанию температура/давление/вибрация попадают в разные категории (норма/предупреждение/неисправность), итоговым состоянием считается самая серьёзная из трёх категорий.
- Почему: при независимой генерации шума по каждому параметру (см. `simulator.py`) параметры иногда расходятся по категориям; для мониторинга безопаснее не занижать состояние — консервативный выбор «худшее из трёх», а не голосование или взгляд только на температуру.
- Затронуто: новый модуль логики состояний (Этап 2).

## 2026-09-21 — Пороги состояний по датчикам
- Решение: границы между состояниями — середина между соседними средними из Таблицы 1 (раздел 3.2 НИР), округлённая: температура 74 / 83, давление 5.4 / 6.2, вибрация 0.7 / 1.2. Ниже нижней границы — «норма», между границами — «предупреждение», выше верхней — «неисправность».
- Почему: реальная Таблица 1 из `НИР_Зеленин_v5.docx` даёт норма 69.69±2.72 / предупреждение 78.43±3.54 / неисправность 88.12±5.34 (температура, аналогично для давления и вибрации). Середина между соседними средними для температуры даёт 74.06 и 83.27 — совпадает с примером куратора («норма примерно до 74, предупреждение до 83»), значит метод рабочий; тот же метод применён к давлению и вибрации. Проверено на `data_raw.csv` (300 записей, по 100 на состояние) — метод устойчив, хотя границы состояний по сырым данным слегка перекрываются (это ожидаемо: сам НИР показывает, что состояния различимы в среднем, а не по жёсткой границе одного показания).
- Затронуто: таблица `thresholds`, модуль определения состояния (Этап 2).
